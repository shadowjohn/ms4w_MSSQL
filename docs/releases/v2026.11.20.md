# ms4w_MSSQL v2026.11.20

本版將 PHP Windows **8.3.36-1 更新至 8.3.37 TS x64 VS16**，修補 CGI、Date、Session、Phar、SOAP 與 Streams 等安全問題。兩個自製 SQLite extension 同步以 8.3.37 source／development pack 重編，保留 SQLite 3.54.1、RTree、PDO SpatiaLite 與 SQLSRV 支援。

## 更新內容

- 依[PHP 官方 changelog](https://www.php.net/ChangeLog-8.php#8.3.37)更新 PHP runtime，包括 CGI PATH_INFO 記憶體存取、timezone cache use-after-free、Session 處理、PHAR 簽章、SOAP 及 URL／HTTP header 處理修補。同版 FPM 修補不代表本 Windows Apache 部署使用 FPM。
- PHP 套件內的 zlib 更新為 1.4；curl 8.23.0、Brotli 1.2.1、libzip 1.12.1 沿用官方 ZIP 提供的版本。
- 重編 `php_pdo_sqlite.dll`、`php_sqlite3.dll`，兩者均回報 8.3.37；SQLite engine 維持 3.54.1。保留 PDO `load_extension()`、open_basedir authorizer 及 RTree。
- 重編腳本新增 `-PhpVersion 8.3.37`，核對 source 與 development headers 的版本一致；原本未傳參數的 8.3.36 行為保留。
- 更新 PHP runtime 清冊、SBOM、版本檢查與重編文件。官方 ZIP、source、development pack 的 SHA-256 均符合官方 release index，來源及重編產物 hash 見 [PHP 8.3.37 更新說明](../php-8.3.37-upgrade.md)。
- Apache 2.4.71、Apache 額外模組、app-local VC runtime 14.52.37029、SQLSRV/PDO_SQLSRV 5.12.0 與 GIS 相依檔保持原版。

## 正式機更新範圍

若正式機已在 **v2026.11.13** 基線，這次只需更新 `Apache/php` 中有差異的管理檔案，以及根目錄的 `PHP_RUNTIME.json`。不需要同步 Apache/bin、Apache/modules、CGI 或 VC runtime。

- 使用本版 MS4W 發行包的 PHP 檔案，其中包含已重編的兩個 SQLite DLL；不要改用官方 PHP ZIP 的原始 SQLite extensions，也不要保留舊版本的兩個自製 DLL。
- 保留正式機的 `php.ini`、OpenSSL／CA 自訂設定、SQLSRV、站台資料與額外 GIS 檔案。不要整目錄刪除、鏡像清空或無差別覆蓋正式機設定。
- 先備份並停止共用此 PHP 的 IIS 集區、Apache、CLI worker 與排程，確認 DLL 釋放再替換。更新後恢復服務，驗證實際 Web SAPI、RTree／SpatiaLite、網站流程及 DB。
- 較舊或另有客製的主機需先比對清冊與 ABI；完整 Release ZIP 不代表可以直接覆寫主機所有設定。

- 先前本機已通過候選 CLI 10/10、runtime 8/8、隔離 Web 16/16、記憶體 GIS 27/27；81 個 PHP payload 雜湊符合，25 個設定／VC／SQLSRV／本機 GIS 檔維持原 hash。CLI 模組清單與原設定一致。
- 本機其後出現 Apex One「新發現程式」執行拒絕。安裝的 `php.exe` SHA-256 為 `54db1035722e402a7e6d65eaa6b79f4918563387aabf2ffc479de0f2d30519fb`，與已驗證的官方 ZIP 內 EXE 完全一致；不能將此狀態寫成本機目前可正常執行。管理端仍需依組織政策評估新版程式的核准或信譽資料。
- 本次維持防護設定，由 GitHub Windows runner 執行發布時的 runtime 與解壓套件驗證；公開資產另下載核對 SHA-256、來源 commit、四份清冊與 payload。沒有為了本機執行而改白名單、停用防護或改名程式。

- 未執行 exploit PoC，沒有連線真實 MSSQL，也未驗收其他主機、IIS 或 production；沒有變更 IIS 集區或排程設定。
